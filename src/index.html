    TRANSPARENCY BY DESIGN

    What the model does.

    Sample demand · geometry assumed · not calibrated

    Data in this session

      Two separate simulation engines

      SUMO mode: the Python/TraCI pipeline runs Eclipse SUMO 1.24.0 locally and records network geometry, vehicle positions, signals, decisions and metrics. The website replays that saved run with smooth interpolation. Inputs lock during replay; generate a new results file to change the native experiment. The demo contains three controllers across five seeds, using synthetic demand and generated geometry. No field validation is claimed.

      Calibration tools: the Python CLI can fit global headway/gap parameters on training observations and compare queues and network exits on a separate session. These tools are available in the source package; your field data is still required.

      Browser model

      Individual vehicles move along arc-length sampled turning paths, keep left, follow a minimum gap, accelerate, and stop at red signals. Each approach has dedicated left, through and right lanes. One approach is released at a time. Conflicting approaches are held red until the intersection clears.

      Fixed 0.2 s steps. A 120 s loading period precedes measurement. Traffic arrives as seeded Poisson processes, using each imported time bin’s counts, movement and class mix. Lane-changing, pedestrians, bus stops, flyover movements, real road geometry and downstream spillback are outside this model.

      Metric definitions

      Stopped delay: stopped vehicle-seconds (speed below 0.5 m/s), including entry backlog, divided by analysis-window arrivals. Includes unfinished traffic and warm-up carryover waiting within the window; not completed-trip mean delay. Queue: longest stopped tail on each approach, averaged across approaches and time, limited to the modeled road. External backlog is reported separately.

      Throughput: network exits per analysis hour. Different vehicle travel times and warm-up carryover affect short-window estimates. Fuel/CO₂ exports: idle-only estimates using assumed 0.8 L/vehicle-hour and 2.31 kg/L; not a validated Delhi fleet model.

      Browser experiment protocol

      Compare baseline, demand-matched green, a 25% shorter cycle (minimum 80 s), and the combined change. Signals retain four approach phases and 8 s clearance per phase. Each phase gets at least 4 s green; remaining green follows the selected weights. Paired seeds: 2026, 2027, 2028. Variability is a sample standard deviation, not a confidence interval or significance test.

      Before claiming real-world savings

      Survey the actual network and phase plan; calibrate with observed discharge, delay and queues; validate on a held-out day. The Browser model is a custom educational engine; SUMO mode uses actual saved SUMO runs. Both require field calibration before real-world savings can be claimed. The scene is a site-inspired visualization of the IIT Flyover surface junction (Y-35), not a surveyed reconstruction.

      Privacy & portability

      CSV files are parsed locally. No backend or analytics receives your counts. In Browser mode, Project JSON exports normalized demand, inputs and results. In SUMO mode it exports the complete native benchmark, including recordings. Three.js is included locally with its license. Procedural vehicle models are original project code.
